# Migration from localStorage to Supabase + Drizzle ORM

This document describes the complete migration from client-side localStorage persistence to server-side Supabase PostgreSQL with Drizzle ORM.

## Overview

**Before**: Data stored in browser localStorage with key `job-app-assistant:jobs:v1`
**After**: Data stored in Supabase PostgreSQL with Row Level Security (RLS) enforcement

## Data Mapping

### localStorage Key → Database Table

| localStorage Key | Database Table | Notes |
|------------------|----------------|-------|
| `job-app-assistant:jobs:v1` | `job_descriptions` | Array of job objects → normalized table with user_id |

### Legacy Job Interface → JobDescription Schema

| Legacy Field | New Field | Type | Notes |
|--------------|-----------|------|-------|
| `id` | `id` | `uuid` | Generated by database |
| `companyName` | `companyName` | `text` | Direct mapping |
| `jobLink` | `jobUrl` | `text` | Renamed, nullable |
| `jobText` | `description` | `text` | Renamed |
| `createdAt` | `createdAt` | `timestamp` | ISO string → timestamp |
| `updatedAt` | `updatedAt` | `timestamp` | ISO string → timestamp |
| `status` | `metadata.legacyStatus` | `jsonb` | Stored in metadata for compatibility |
| `tailoredResume` | `metadata.legacyTailoredResume` | `jsonb` | Stored in metadata |
| `coverLetter` | `metadata.legacyCoverLetter` | `text` | Stored in metadata |

### New Fields Added

| Field | Type | Purpose |
|-------|------|---------|
| `userId` | `uuid` | Multi-tenant isolation via RLS |
| `jobTitle` | `text` | Job position title (defaults to "Software Developer") |
| `location` | `text` | Job location (nullable) |
| `salaryRange` | `text` | Salary information (nullable) |
| `employmentType` | `text` | Full-time, part-time, etc. (nullable) |
| `remote` | `boolean` | Remote work flag |
| `requirements` | `jsonb` | Structured requirements array |
| `benefits` | `jsonb` | Structured benefits array |
| `metadata` | `jsonb` | Legacy data and additional fields |

## Security Enhancements

### Row Level Security (RLS)
All tables now have RLS enabled with policies ensuring:
- Users can only access their own data (`auth.uid() = user_id`)
- Cross-user data isolation enforced at database level
- No data leakage between users

### Authentication Integration
- All data operations require authenticated user
- User ID automatically injected from Supabase auth session
- Server-side validation and authorization

## Migration Process

### For Existing Users
1. **Automatic Detection**: MigrationBanner component detects localStorage data
2. **User Consent**: Users can choose to migrate or dismiss
3. **Data Conversion**: Legacy data converted to new schema
4. **Cleanup**: localStorage cleared after successful migration
5. **Verification**: Data appears in dashboard

### Migration Utility Functions
```typescript
// Check for legacy data
const legacyData = checkForLegacyData()

// Migrate data
const result = await migrateFromLocalStorage(legacyData)

// Clear localStorage
clearLegacyData()
```

## Database Schema

### job_descriptions Table
```sql
CREATE TABLE job_descriptions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  company_name TEXT NOT NULL,
  job_title TEXT NOT NULL,
  job_url TEXT,
  description TEXT NOT NULL,
  location TEXT,
  salary_range TEXT,
  employment_type TEXT,
  remote BOOLEAN DEFAULT FALSE,
  requirements JSONB,
  benefits JSONB,
  metadata JSONB,
  created_at TIMESTAMP DEFAULT NOW() NOT NULL,
  updated_at TIMESTAMP DEFAULT NOW() NOT NULL
);
```

### RLS Policies
```sql
-- Users can only access their own job descriptions
CREATE POLICY "Users can view own job descriptions" ON job_descriptions
  FOR SELECT USING (auth.uid() = user_id);

CREATE POLICY "Users can insert own job descriptions" ON job_descriptions
  FOR INSERT WITH CHECK (auth.uid() = user_id);

CREATE POLICY "Users can update own job descriptions" ON job_descriptions
  FOR UPDATE USING (auth.uid() = user_id);

CREATE POLICY "Users can delete own job descriptions" ON job_descriptions
  FOR DELETE USING (auth.uid() = user_id);
```
